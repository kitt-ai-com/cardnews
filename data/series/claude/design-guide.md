## 2. 레이아웃 패턴 (사용 중)

이 시리즈에서 **현재 적극 사용 중인 패턴**:

### `cover` — 표지

```
┌─────────────────┐
│ 풀 배경 이미지   │
│                  │
│ [태그]    top:60 │
│                  │
│ ────             │ 텍스트 영역 시작 (하단)
│ [메인 카피]       │ 90~110px, line-height 1.05
│                  │
│                  │ ← title-subtitle 간격 ≥ 80px
│ [서브 카피]       │ 34px (본문과 동일), `--muted`
│                  │
│ [@핸들]  [01/N] │
└─────────────────┘
```
- 이미지: 풀 배경, 텍스트 영역(주로 하단 60%) 비워두기.
- 카피: 1초 멈추는 후킹. `<accent>`로 핵심 단어 강조.
- **title-subtitle 사이 80px 이상.** 28px 같은 좁은 간격은 압박감 줌 (피드백 반영).
- subtitle은 본문 표준(34px) 사용 — 시리즈 내 폰트 사이즈 일관성.

### `P1` — 본문 (이미지 + 텍스트)

```
┌─────────────────┐
│                  │
│ [상단 이미지]     │ ← 0~50%, 하단으로 그라디언트 fade
│                  │
│ [태그]    top:60 │
│                  │
│ [메인 제목]       │ ← top: 720 (이미지 끝~제목 사이 여유)
│                  │
│                  │ ← title-body 간격 ≥ 200px (너무 붙으면 답답)
│ [본문 (3~4문장)] │ ← top: 980, 34px
│                  │
│ [@핸들]  [N/N] │
└─────────────────┘
```
- 이미지: 상단 50%, 아래는 `linear-gradient(to bottom, transparent, var(--bg))` 페이드
- 본문: **34px**, `--muted` 색상. 28~30px는 작게 느껴짐 (피드백 반영, 2026-05-01).
- title 끝과 body 시작 사이 200px 이상 간격 — 시각적 숨통.

### `P3` — 체크리스트 / 리스트

```
┌─────────────────┐
│                  │
│ [태그]    top:60 │
│ [메인 제목]       │ ← top: 200, 한 페이지 한 메시지
│                  │
│                  │ ← title-list 간격 ≥ 250px 필수
│                  │   (위에 붙으면 답답 — 피드백 반영)
│ ✓ 항목 1         │ ← top: 500, 32px
│ ✓ 항목 2         │ ← gap: 38px, line-height: 1.45
│ ✓ 항목 3         │
│ ✓ 항목 4         │ (3~5개 권장)
│                  │
│ [@핸들]  [N/N] │
└─────────────────┘
```
- 이미지 없음 (본문 정보 밀도가 핵심).
- 체크박스 22px 라임, 항목당 1~2 문장.
- 단순 키워드 나열 금지.
- `<b>강조어</b>`는 `--accent`, `<code>슬래시</code>`는 라임 배경 칩.
- **제목 끝과 리스트 시작 사이 250px 이상 간격** — 너무 가까우면 시선 정체.

### `cta` — 마무리

```
┌─────────────────┐
│ [반투명 배경 이미지] │
│                  │
│ [태그]           │
│ [큰 메인]         │ ← 110px (압도적 마무리)
│                  │
│                  │
│ [짧은 안내]       │ ← 본인 행동 유도 / 출처
│                  │
│ [@핸들]  [N/N] │
└─────────────────┘
```

### `P2` — 3-열 비교 카드

```
┌─────────────────┐
│ [태그]            │
│ [메인 제목]        │ ← top: 200
│                  │
│                  │ ← title-cols 간격 ≥ 250px
│ ┌────┐┌────┐┌────┐
│ │ 아이콘 │ × 3
│ │ 이름  │
│ │ 설명  │
│ │ 메타  │
│ └────┘└────┘└────┘
│                  │
│ [@핸들]   [N/N] │
└─────────────────┘
```
- 3개 항목을 **나란히 비교**할 때만 사용. 2개 비교는 좌우 split, 4+ 항목은 P3 리스트.
- 카드 배경 `rgba(255,255,255,0.04)` + 라임 보더 `rgba(196,255,61,0.18)`.
- 아이콘은 라임 박스(80px) 안에 단일 글리프 (`/`, `⚡`, `↻` 등).
- 카드 안 위계: 아이콘 → name(라임 38px 800) → desc(흰 26px) → meta(muted 22px, 카드 하단).
- 시리즈 시각 리듬을 위해 P1·P3 외에 한 카드뉴스에 **최대 1번** 권장.

### `P6` — CTA 알약 버튼

```
┌─────────────────┐
│ [반투명 배경 이미지] │
│                  │
│ [태그]            │
│ [큰 메인]         │ ← 110px (압도적 마무리)
│                  │
│ [짧은 안내]       │
│                  │
│ ╭─────────────╮  │
│ │ 행동 카피 → │  │ ← 알약 라임 버튼, 110px 높이, 38px 800
│ ╰─────────────╯  │
│                  │
│ [@핸들]   [N/N] │
└─────────────────┘
```
- `cta`의 강화 버전 — 행동을 명시할 때 사용.
- 버튼 텍스트: 동사 + 화살표 (`저장하고 따라하기 →`, `링크 열기 →`).
- 라임 그린 풀 배경 + 검정 텍스트 + `box-shadow: 0 0 60px rgba(196,255,61,0.25)` 글로우.
- "30분 단축"같은 정량 클레임은 근거 있을 때만. 보통은 "하나만 시작" 같은 부담 낮춘 카피.

### `P8` — 비교 표 (TABLE)

```
┌─────────────────┐
│ [태그]            │
│ [메인 제목]        │ ← top: 280
│                  │
│        Claude    Codex  ← 헤더 행 (accent / alt 색)
│ ─────────────────────  ← 구분선 (라임)
│ 만든 곳 Anthropic OpenAI
│ 모델   Claude 4.x GPT-5
│ 강점   ...        ...
│        sub-line   sub-line
│ 한계   ...        ...
│                  │
│ [callout: 한 줄 요약]
└─────────────────┘
```
- 항목별 axis(좌측 22%) + 두 컬럼 비교.
- `.sub` 작은 회색 글씨로 부가 설명 (font-size: 22px).
- 헤더 색: A컬럼 라임, B컬럼 alt 파랑 → 정보 구분.
- 사용처: 두 도구·옵션·접근법의 정량/정성 비교.
- callout 슬롯에 균형된 takeaway (한쪽 우월 X).

### `P9` — 세로 스택 카드 (rich rows)

```
┌─────────────────┐
│ [태그]            │
│ [메인 제목]        │

- `[번호][이름+설명][뱃지]` 그리드.
- P2(3-열)가 너무 좁을 때 P9 사용.

### `P11` — 번호 단계 + 코드

```
┌─────────────────┐
│ [태그]            │
│ [메인 제목]        │
│                  │
│ [01] 무엇을 한다  (note: 부가 설명)

│      $ 명령

- 단계별 워크플로우 (4-5 step).
- 번호 박스 + 짧은 액션 + 코드.

### `P15` — 입문자 오해 깨기 (Myth/Reality)

```
┌─────────────────┐
│ [태그]            │
│ [메인 제목]        │
│                  │
│ ┌── 01 ──────────────┐
│ │ ✗ 잘못 알려진 것      │
│ │ ✓ 사실: ...           │
│ └──────────────────────┘
│ ┌── 02 ──────────────┐
│ │ ...                  │
│ └──────────────────────┘
└─────────────────┘
```
- 입문자가 자주 하는 3가지 오해를 ✗→✓ 패턴으로.
- 한국 입문자 분석에서 자주 나오는 misconception 우선.
- 시리즈 신뢰도 ↑ (선제 해소).
- 사용 예: Claude Code 처음 시작 03 카드 ("처음 듣는 사람이 착각하는 3가지").

### 미사용 (라이브러리 보관)
- `P4` (저장 유도 배지)
- `P5` (공식 + 프롬프트 카드)

→ 필요 시 시리즈 가이드에 추가, 처음부터 다 안 씀.

### 레이아웃 다양성 규칙
- **한 카드뉴스에 본문 레이아웃 ≥ 2종** (예: P1 + P3 섞기)
- 같은 패턴이 3페이지 연속이면 지루. P1 → P3 → P1 → P3 식으로 교차.
- **P1 + P3 만 반복하면 단조로워짐** — 비교 페이지엔 P2, 마무리는 P6를 한 번씩 끼워주면 시각 리듬 살아남.

### `<accent>` 강조 한도
- **페이지당 최대 2~3개**. 5개 이상 강조하면 강조 효과가 사라짐.
- 같은 페이지에서 같은 단어를 두 번 강조하지 말 것 (한 번이면 충분).

### P1 본문 — 단락 본문 vs 키-밸류 불릿
- 한 페이지에 정보가 3가지 (어디에 / 어떻게 / 권한 등)면 **키-밸류 불릿**으로:
  - `<span class="k">어디에</span><span>...</span>` 형태
  - 시선이 빠르게 스캔 가능, 문서 캡처처럼 안 보임.
- 한 가지 메시지면 그냥 단락 body.

## 3. 카피 스타일 가이드

### 톤
- **친근하지만 전문적.** 입말 우선 ("이거 모르면 손해" OK, "본인은 모르고 있을 수 있다" X).
- 한자어 → 한글로 ("자동 실행" OK, "자동 호출 처리" 가급적 회피).
- 숫자·예시 적극. "그래서 뭐가 좋은지" 구체적으로.

### 길이 규칙
| 위치 | 길이 |
|---|---|
| **표지 title** | 2~3줄, 한 문장 |
| **본문 title** | 2~3줄, 한 메시지 |
| **본문 body (P1)** | 3~4 문장 |
| **list 항목 (P3)** | 항목당 1~2 문장. 키워드 한 단어 금지. |
| **CTA body** | 짧게. 행동 + 출처 |

### 후킹 (Hook) 패턴
- **숫자 충격:** "5배", "30분", "3초"
- **손실 회피:** "모르면 손해", "이거 안 쓰면 매일 30분 낭비"
- **권위 인용:** Anthropic 공식 / 사용자 후기
- **호기심 유발:** "한 가지 차이"
- **Anthropic voice 차용 (Claude 시리즈 우선 룰):** 공식 docs 첫 문장의 키워드를 1장 후킹에 그대로 가져오기 — Anthropic Claude Code overview는 "agentic coding tool that **reads / edits / runs** ... available in your **terminal, IDE, desktop app, and browser**"가 첫 문장. → 1장 후킹은 "내 코드를 통째로 **읽고·고치는** AI" 같이 차용. 공식 voice와 정렬되면 신뢰도 ↑.

### 시리즈 일관성 (사실 인지) 룰

**문제 사례 (v7 → v8 학습):** 1장에서 "터미널 AI"라 framing → 5장에서 "데스크탑 앱이 더 쉽다" 노출 → 독자 신뢰 손상.

**룰:** 후속 페이지에서 등장할 핵심 사실(특히 환경·플랜·가격)은 **1-2장에서 미리 노출**. 늦게 등장하면 surprise가 confusion이 됨.

| 사실 | 1-2장에 노출해야 |
|---|---|
| 멀티 환경 (터미널 외) | "터미널·IDE·앱·웹 어디서든" 1장 sub에 |
| 유료 (Free 미포함) | 2장 callout에 "Pro $20/월 이상" |
| API 키 불필요 | 입문자 오해 카드 또는 7장 step1 note |

### 강조 마크업
- `<accent>강조어</accent>` → 라임 그린 인라인. **페이지당 최대 2~3개.** 너무 많으면 강조 효과 사라짐.
- `<code>/명령어</code>` → 라임 배경 칩. 슬래시 명령·파일 경로·환경 변수에만.
- 제목 줄바꿈 `<br>`은 의도적으로. 한 줄이 너무 길면 시선이 끊김.

### 정보 충실도 (sourceText 있을 때)
- 사례·인용·수치·배경을 슬라이드에 분산.
- 한 장당 원문 정보 2~3 포인트.
- "요약"이 아닌 "전달".

### 숫자엔 맥락 1문장
- ❌ "매출 6,000억 원"
- ✅ "매출 6,000억 원 — 창업 9개월 만에 시리즈 A 없이 AI 도구만으로 운영한 결과"

## 3.5 정보 구조 패턴 (Information Patterns I1~I6)

> 시각 패턴(P1~P7)과 **직교**한다. 같은 P1 레이아웃이 I1을 담을 수도, I3를 담을 수도. 페이지의 `copyIntent`와 함께 어떤 I-pattern이 어울리는지 결정.
> 자세한 정의는 `docs/superpowers/specs/2026-05-02-claim-ledger-revision.md` §7.

### Claude 시리즈에서 자주 쓸 패턴 (우선순위)

| ID | 정보 구조 | Claude 시리즈에서 쓰임 | 어울리는 시각 |
|---|---|---|---|
| **I1** Claim + Evidence | 큰 주장 → 근거 칩 → 출처 주석 | 새 기능 발표·벤치마크 인용 | P1, P3 |
| **I3** Mechanism | 원인 → 작동 → 결과 (3단) | 작동 원리 설명 (Skills/Hooks/Loop의 메커니즘) | **P2** (3-열) |
| **I4** Myth / Reality | 흔한 오해 vs 실제 + 주의점 | "AI는 이런 거" 류 오해 정정 | P1 분할, P2 2-열 |
| **I5** Decision Guide | 언제 쓰나 ✓ / 언제 안 쓰나 ✗ | "이 도구를 언제 써야 하나" | P3 (✓/✗ 색상 분리) |
| I2 Before / After | 이전 / 이후 / 차이의 의미 | 도구 도입 전후 비교에 좋음 | P1 분할, P2 2-열 |
| I6 Case Breakdown | 사례 → 왜 → 배울 점 | 실제 사용 사례 소개 | P1 큰 이미지 |

### 페이지마다 어떤 I-pattern을 썼는지 표기 권장
- 디자인 가이드 안의 "첫 살아있는 예시"에 페이지별 I-pattern을 함께 적기.
- M3 이후 Editorial Review가 I-pattern별 검증 룰을 적용.

## 3.6 Claim 정책 (Claude 시리즈)

### 신뢰 가능한 1차 출처 (`trustedDomains`)

```
code.claude.com/docs       — Claude Code 공식 문서
docs.claude.com            — Claude API 문서
anthropic.com/news         — 회사 공식 블로그·발표
www.anthropic.com/research — 논문·리서치
```

이 출처는 `trustLevel: "primary"`로 기본 설정 → fact-check `skip` (수치만 quick-check).

### 평가어 사용 정책

이 시리즈는 **개발자/AI 도구 관심층** 대상이라 마케팅 톤보다 **정직한 톤**. 다음 평가어는 **근거 없으면 사용 금지**:

- 강력하다, 완벽한, 혁신적인, 필수다, 단연
- 압도적, 최고의, 가장 좋은, 획기적인, 엄청난
- 방대한, 총망라, 다 갖춘

근거가 있을 때만 (벤치마크 수치 + 출처 함께) 사용.

### Claim 추출 시 주의 (Claude 시리즈 한정)

- **버전·기능명**은 항상 `risk: "outdated"` + `asOf` 표기. Claude 모델/도구는 빠르게 업데이트됨.
- **개인 설치 스킬·플러그인**(예: 사용자가 만든 슬래시 명령)은 절대 "공식 예시"로 인용 X. `scope` 태그에 `installed-by-user`로 마킹해 Copywriter가 인용 제외.
- **Anthropic 외 출처**는 항상 `confidence` 한 단계 낮춤 — Claude의 행동 변화는 공식 발표가 1차 진실.

## 5. Do / Don't

### ✅ Do
- **Claim Ledger 먼저, outline 나중.** 카드뉴스 작성 전에 다룰 사실/숫자/인용/해석/추천을 모두 Claim으로 분리.
- 매번 사실 검증 (공식 문서·WebFetch·`claude-code-guide` 서브에이전트). 머릿속 지식만으로 카피 적지 말 것.
- 페이지마다 `copyIntent` 명시 (hook/context/definition/comparison/mechanism/evidence/example/warning/action/cta).
- "주장 + 메커니즘 + 근거 + 의미" 4요소 한 페이지에.
- `<accent>` 한 페이지에 1~2개만.
- 본문 레이아웃 2종 이상 섞기 + 정보 패턴(I1~I6) 한 카드뉴스에 ≥2종.
- 이미지 영역과 텍스트 영역 분리 — 합성된 글자 박힌 이미지 X.
- 푸터 핸들 + 페이지 번호 모든 페이지에 표시.
- 카피는 한국어로 짧고 호흡 빠르게.

### ❌ Don't
- 표지에 정보 다 박기 (1초 안에 다음으로 넘기게).
- 한 페이지 두 메시지.
- 단순 키워드 나열 (1~2 문장의 짧은 설명 동반).
- 사용자가 직접 만든 개인 스킬을 "공식 예시"로 소개.
- 같은 레이아웃 3연속.
- 제목·본문에 `<accent>` 5개 이상 — 강조 효과 사라짐.
- "~는 ~합니다" 격식체 (입말로).
- AI 표현 그대로 — "방대한", "혁신적인", "총 망라" 등 평가어를 근거 없이.
- **근거 없는 단정.** "X는 가장 강력하다" → 벤치마크 + 출처 없으면 금지.
- **interpretation을 fact 형식으로.** "~이다"가 아니라 "~로 보인다", "~할 수 있다"처럼 약하게.
- **Claim Ledger 비어있는 페이지.** 모든 페이지는 ≥1 Claim id 참조.

## 7. 새 카드뉴스 만들 때 체크리스트

워크플로우는 spec v2 (claim-ledger-revision)의 6단계 파이프라인을 따르되, 이 가이드 기준으로:

- [ ] **Step 0 — Source Digest** — 공식 출처 fetch (claude-code-guide / WebFetch / 사용자 sourceText). URL 분류로 trustLevel 결정.
- [ ] **Step 1 — Claim Ledger** — 모든 사실/숫자/인용/해석/추천을 Claim 레코드로 추출. type/confidence/risk/sourceRef 부여. audienceQuestion 결정.
- [ ] **Step 2 — Analyst** — thesis 한 문장 + narrativeArc 6단 + 페이지 분해 (5~13장, copyIntent 명시, claims[] 매핑, 본문 레이아웃 ≥2종 + I-pattern ≥2종).
- [ ] **Step 3 — Copywriter** — 페이지 하나씩 따로. 주장+메커니즘+근거+의미 4요소. `<accent>` 절제, 한 문장 2줄 이내, 숫자엔 맥락. copyIntent에 따라 문장 구조 다르게.
- [ ] **Step 4 — Editorial Review** — unsupported claim, low-confidence 단정, outdated 미표기, 평가어 근거 누락, unused claim, thin arc 검사. 위반 시 Copywriter 재호출.
- [ ] **Step 5 — Image Director** — 텍스트 영역 보존 지시, imageStyle 강제, 추상 표현 매핑.
- [ ] **Step 6 — 합성** — Pretendard 로드 확인, 라임 액센트 위치 일관, 푸터 핸들 표시.
- [ ] **최종 점검** — 한 페이지 한 메시지인가, 위계 명확한가, 같은 레이아웃 3연속은 아닌가, 카피에 AI스러운 평가어 없나, **모든 페이지가 ≥1 Claim 참조하는가**.
